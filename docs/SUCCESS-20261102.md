## 关键步骤（可复现）

1. **准备 blobs**：从第三方项目 `Freeze-Over/nfc-15pro-st54l` Release 1.3 的 `nfc-odm17.zip` 提取小米 17（pudding OS3.0.319 / Android 16）NFC 栈 6 个文件（本实验只用到前 5 个，未替换 `Nfc_st.apk`）：
   - `nfc-service-st`（86,400 B，`sha256 180fd757…3bae88`）
   - `nfc_nci.st21nfc.st.so`（283,656 B，`e3ea02c6…272def`，含 `stpropnci_*` 引擎）
   - `st54l_fw.bin`（260,157 B，`22a9e85d…2fbe4d`，fileFwVersion `0x02072128`）
   - `libnfc-hal-st.conf`（7,177 B，`fd2db7db…c188c6f9`）
   - `st54l_conf.txt`（6,771 B，`035aba67…6d0007`）
   全部放在设备 `/data/local/tmp/nfcmod/`。
2. **运行时 overlay（root，不写分区）**：tmpfs（`suid,dev`）+ 逐文件 `chcon` 到目标 SELinux 类型（`hal_nfc_default_exec` / `vendor_file` / `vendor_configs_file`），再 `mount --bind` 覆盖 `/odm/...` 5 个路径。**必须用 `ls -Z` 校验标签**，否则 init 会拒绝启动 `nfc_hal_service`（之前 haotian 模块失败的原因）。
3. **重启 HAL**：`kill $(pidof android.hardware.nfc-service-st)` → init 用 pudding HAL 重新拉起（`ST21NFC AIDL HAL Version 25Q2-BP2A-20250620-PRC-25W25p0`），启动时自动把 ST54L 芯片固件从 **02.04.1188 升级到 02.07.2128**，然后重启 `com.android.nfc`（dada 自己的 Android 17 框架进程）即可正常连上 HAL。
4. **配置 7A 轮询帧**：`q13.jar`（`sendVendorNciMessage(1, 0x0F, 0x01, {0x13, 0x01, 0x2A, 0x02, 0x0A, 0x7A})`）→ `resp=1300`；GET 0x15 读回 `012A020A7A`。
5. **App 刷屏（InkNfcLab-0.5.4）**：
   - 0.5.4 在 ISO-DEP 连接后**保场充能 2000 ms** 再发 D1（否则 D1 返回 6401/6403）；
   - D1 失败重试 3 次；
   - **APC 实验档设为 +2**（调试面板里切换）：原厂档在 DE 阶段返回 `68CA` 低电压，+2 后成功（用户手动完成）。
6. 结果：DE 返回 `009000`，刷新完成；App 自动恢复 APC 与轮询配置（逐字节读回一致）。

## 重启后如何恢复（脚本已放设备）

- 重新应用 overlay 并武装 7A：`adb shell su -c 'sh /data/local/tmp/nfc-overlay-apply.sh'`（日志 `/data/local/tmp/nfc-overlay.log`）。
  该脚本会：挂载 tmpfs、复制+chcon、**校验 HAL 服务标签失败则中止（不挂载，避免再次弄坏 NFC）**、bind mount、重启 HAL/NFC 服务、发送 0x13。
- 完全回滚到原厂文件：`adb shell su -c 'sh /data/local/tmp/nfc-overlay-remove.sh'`。
- 主机副本：`stack-port/os3-success/nfc-overlay-apply.sh`、`nfc-overlay-remove.sh`。

## 仍待做（已被上节持久化模块取代）

当前方案是**运行时 overlay**，重启后需再次执行脚本。若要“开机自动生效”，需要做 KernelSU 模块；但因为上一版 haotian 模块在 dada 的 **post-fs-data 阶段 chcon 失败**导致 init 拒绝启动 HAL（详见 `CRASH-ANALYSIS-20261102.md`），持久化模块必须：
1. 在 post-fs-data 阶段只做**可校验的**挂载，标签不对就整体放弃；
2. 或者改为 late_start（service.sh）阶段 relabel + `ctl.start nfc_hal_service`，但需处理开机时原厂 HAL 与原厂 FW 文件对 2.7 芯片的比较/回写行为；
3. 内置日志与一键回滚。

在完成并验证前，建议继续用“手动/脚本 overlay + App 刷屏”的方式。

## 2026-11-12 补充：系统 OTA 到 OS4.0.3.0 后 NFC 故障与模块 v1.2 修复

用户 OTA 到 `OS4.0.3.0.XOCCNXM` 后 NFC 打不开（`dumpsys nfc` → `Can't find service: nfc`）。
排查结论：

- **OTA 没有改动 NFC 厂商文件**：把 /odm 的 dm 设备只读挂载后核对，5 个原厂文件
  大小与 SHA-256 与旧版完全一致；芯片固件也仍是 `02.07.2128`。
- 真正原因：模块 **v1.1 的 `service.sh` 在开机启动过程中 kill HAL 与
  `com.android.nfc`**，在新系统启动时序下导致 NfcService **startup ANR**
  （dropbox：`com.android.nfc ... failed to complete startup`），随后 `nfc`
  系统服务未注册。
- 修复：模块 **v1.2** 移除开机阶段所有 HAL/NfcService 重启逻辑（`service.sh` 只
  验证/记录，`action.sh` 只重放 overlay，`post-fs-data.sh` 幂等）。
- 验证：重启后 `mState=on`、HAL 正常、FW `02.07.2128`、`0x13` 返回 `1300`，
  NFC 与刷屏能力恢复。

详见 [OTA-OS4.0.3.0-incident.md](OTA-OS4.0.3.0-incident.md)。
